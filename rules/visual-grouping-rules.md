# 视觉分组与层级修正规则

## 核心原则

Figma 图层树不是 Android View 树。生成 XML 时必须以视觉归属和交互语义重建结构，不得机械照搬 Figma 的父子层级。

常见设计稿问题：

- 按钮文字在一个 Group，按钮背景在另一个 Group。
- 卡片背景被放在页面根层级，卡片内容散落在其他层级。
- 装饰背景、遮罩、图片、文本分属不同 Frame，但视觉上属于同一组件。
- 图层顺序只服务视觉遮挡，不表达真实容器关系。
- 自动布局和 Group 混用，导致实际分组不可信。

## 判断视觉归属的证据

按优先级综合判断，不使用单一信号做结论（android_tree.json 为唯一权威数据源，见 `rules/android-tree-guide.md`）：

1. 几何关系（android_tree 精确数据，优先）
   - 背景 bounds 是否包含文本、图标或图片。
   - 元素中心点是否落在背景 bounds 内。
   - 元素之间是否形成稳定对齐、固定间距或同行/同列关系。

2. Z 轴关系（android_tree children 顺序）
   - 背景通常在下层，文本和图标在上层。
   - 悬浮角标、关闭按钮、徽标可以视觉覆盖在图片或卡片上。
   - 不能因为背景和文本不是同一父节点，就拆成无关 View。

3. 语义角色
   - 文本如”确定””获取定位””立即购买”通常与附近圆角背景组成按钮。
   - 图标加标题加副标题常组成列表 item 或卡片。
   - 顶部返回图标、标题、右侧操作通常组成标题栏。

4. 命名线索
   - 图层名可辅助判断，但不能覆盖几何和坐标证据。
   - 无意义图层名如 `Group 3`、`Vector 101` 不得直接作为资源名或 View ID。

5. 截图证据（辅助，仅在前四项证据不足时补充视觉直觉）
   - 某些元素是否视觉上被同一个背景、卡片、按钮或弹窗包住。
   - 是否存在明显的边界、圆角、阴影、色块、遮罩或同一点击区域。
   - 截图不提供精确数值；精确坐标/尺寸/颜色/层级一律以 android_tree 为准。

## 重组策略

### 背景与内容分离

如果背景层与内容层分离，但满足以下条件，应在 Android 中重组为同一容器：

- 背景 bounds 包含内容 bounds。
- 内容在视觉上依附该背景。
- 内容与背景共同形成按钮、卡片、标签、弹窗或输入框。

Android 生成策略：

- 纯色、圆角、描边背景：生成 shape drawable，挂到容器 `android:background`。
- 复杂图片背景：使用 ImageView 放底层，内容通过 ConstraintLayout 叠加。
- 可点击区域：点击 ID 放在整体容器上，而不是只放文字或图标上。

### 卡片内容散落

如果一个卡片的背景、主图、标题、价格、按钮分散在不同父节点，应按视觉卡片重组：

- 外层生成 `ConstraintLayout` 或项目已有 Card 容器。
- 背景 shape 或图片作为容器背景。
- 内部元素按实际 bounds 建约束。
- 重复卡片拆为 `item_*.xml`，父页面使用 `RecyclerView` 或 `ViewPager2`。

### 顶部背景与标题栏

顶部大背景图常与标题、返回按钮、状态信息处于不同层级。处理方式：

- 大背景图作为根布局底层 ImageView。
- 标题栏控件约束到根布局顶部或安全区。
- 如果背景只起装饰作用，不把它当作标题栏父容器。

### 装饰层

装饰性图层不一定生成独立 View。满足任一条件可合并或降级：

- 对交互无影响。
- 可以由父容器背景、shape、padding、elevation 表达。
- 生成独立 View 会显著增加层级且无语义价值。

必须保留的装饰：

- 品牌背景、复杂渐变、插画、遮罩图片。
- 影响点击区域理解的按钮背景。
- 影响组件边界的卡片背景和弹窗背景。

## 决策产物要求

重组原因**在结构确认摘要（终端）逐条给出**，须含：归组结论 + 依据（bounds 包含 /
视觉重叠 / 重复模式）+ 涉及的源节点 id。示例措辞：

> 按钮 = 背景[21:169] + 图标[21:170] + 文字[21:171] 合并为一个可点击容器
> （背景 bounds 包含图标和文字，Figma 分属不同层级，Android 合为一处）。

**禁止把结论写回任何脚本产物 JSON**（`android_tree.json` / `assets.json` 是只读事实源，
见 AGENTS.md「Agent 不得手改脚本产物」）。若需沉淀实现级提示（如"某区域建议 RecyclerView"），
写入 `layout_analysis.json` 的 `implementation_hints` 字段（结构见
`schemas/layout-analysis-schema.md`），不要发明新字段。

## 禁止行为

- 禁止按 Figma 父子层级原样生成深层 ViewGroup。
- 禁止因为背景和文字分属不同父节点就拆成两个无关区域。
- 禁止把装饰 Group 直接变成无意义 FrameLayout。
- 禁止用图层名代替 Android 语义 ID。
- 禁止用截图目测替代 android_tree 精确数据（Hard Rule 17）；截图证据仅作定性补充，不提供坐标/颜色/尺寸。
